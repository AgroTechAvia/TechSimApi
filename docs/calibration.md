# Калибровки и управление в agrotechsimapi 1.1

Пошаговый сценарий запуска, просмотра графиков и переноса профилей находится в
[практической инструкции](calibration_guide.md). Этот документ описывает детали
алгоритмов, хранилища и поведения клиента.

Калибратор входит в установленный пакет. Все команды работают из любой папки;
исходники и каталог `utils` для них не требуются. Установите текущую версию из
репозитория командой `python -m pip install .`. Обычная установка копирует код,
поэтому после следующих изменений её надо повторить. Для разработки используйте
`python -m pip install -e .`.

## Готовая калибровка

```python
from agrotechsimapi import HighLevelSimClient

drone = HighLevelSimClient()                    # встроенная edu-ext
drone = HighLevelSimClient(calibration="edu-constructor")
drone = HighLevelSimClient(calibration="edu")
drone = HighLevelSimClient(calibration="my_drone")
drone = HighLevelSimClient(calibration_path="my_drone.json")
```

Имя `HighLevelClient` также доступно как псевдоним `HighLevelSimClient`.
При необходимости `calibration_dir="/path/to/storage"` задаёт корень хранилища.
Параметры отдельных PID в конструкторе сохраняются и имеют приоритет над
профилем. Добавлены `pid_accel_pitch` и `pid_accel_roll`.

`edu-ext` и `edu-constructor` содержат прежний набор `default`: высота от 18 сентября 2026,
yaw от 18 сентября, ускорение от 24 сентября, скорость и положение от 25 сентября.
`edu` содержит коэффициенты принятой калибровки `my_drone`.
Даты и исходные идентификаторы всех пяти этапов хранятся в `sources`.
У исходных проверок есть статус `needs_review`: он сохранён, хотя пользователь
принял набор. Этот статус не означает, что настройка была прервана, и не запрещает
использование. Подробности проверок находятся в `results`.

## Где лежат файлы

| ОС | Каталог по умолчанию |
|---|---|
| Windows | `%LOCALAPPDATA%\agrotechsimapi` |
| Linux | `$XDG_DATA_HOME/agrotechsimapi`, иначе `~/.local/share/agrotechsimapi` |
| macOS | `~/Library/Application Support/agrotechsimapi` |

`AGROTECHSIMAPI_DATA_DIR` переопределяет каталог на всех ОС. Для отдельной команды
можно указать `python -m agrotechsimapi --data-dir PATH ...`.
Хранилище пользователя общее для его виртуальных окружений. Для изоляции окружений
задайте разные каталоги. В пакет записывать ничего не требуется; обновление pip
не удаляет пользовательские данные.

```text
calibrations/<name>.json       # Версия формата, дата, все 8 PID, настройки, проверки
runs/<session_id>/session.json # Состояние именованного запуска
runs/<session_id>/<run_id>/    # summary.json и CSV каждого этапа
reports/<name>.html            # Автономный снимок графиков
active.json                   # Указатель на последний запущенный сеанс
```

Встроенные `edu-ext`, `edu-constructor` и `edu` поставляются внутри пакета как
ресурсы только для чтения. `edu-ext` используется по умолчанию. Старое имя
`default` работает как скрытый псевдоним `edu-ext`, но не выводится в списке.

```sh
python -m agrotechsimapi calibrations list
python -m agrotechsimapi calibrations show edu-ext
python -m agrotechsimapi calibrations export edu-ext --output drone.json
python -m agrotechsimapi calibrations import drone.json --name my_drone
```

Экспорт переносит коэффициенты, настройки и статистику в JSON. CSV в него не
включаются: для передачи графиков сохраните HTML командой `plot --output ...` и
скопируйте его вместе с JSON. HTML полностью автономен. При импорте файла со
встроенным именем требуется указать новое имя; встроенный набор нельзя перезаписать. Для замены собственного
профиля укажите `--replace`. Исходная дата сохраняется при импорте.

## Новая калибровка

```sh
python -m agrotechsimapi calibrations init-config --output calibration.json
python -m agrotechsimapi calibrate --name my_drone --config calibration.json
python -m agrotechsimapi calibrate --name my_drone --config calibration.json --fly
```

Вторая команда выводит план и настройки, не подключаясь к симулятору.
Третья запускает последовательность **высота → yaw → ускорение → скорость →
положение**. Высота и yaw, как и контуры XY, настраиваются по фазам
**P → проверка/D → проверка/I → валидация**. Каждая оценка строится по трём
повторениям. Между контурами выполняется посадка и новый взлёт.

Для высоты P подбирается по подъёму на 1 м за `2.5 ± 0.5` с. Отсчёт начинается
после фактического отрыва на 3 см, а запись продолжается до служебной посадки;
начальный шаг P равен 0.05. Поиск выполняется проходами вперёд → назад → вперёд
с общим лимитом 100 проб; 60 значений доступны крупному проходу, чтобы сохранить
диапазон коэффициентов после уменьшения шага. Недолёт за 10 с остаётся плохим измеренным результатом.
D отвечает за прекращение колебаний в
полосе 3 см вокруг установившегося уровня. I оценивается после найденного D-времени
успокоения и должен держать целевую высоту в полосе 7 см не менее 70% времени.
Финальная последовательность: `1 → 4 → 3.75 → 1.5 м → посадка`.

Для yaw каждая проба содержит три пары поворотов `+75°/−75°`. Перед каждым
поворотом служебное торможение нейтрализует вращение быстрее 2°/с, а исходный
угол снимается после торможения. P настраивается на время `4.0 ± 0.25` с;
начальный шаг равен 0.25, поиск выполняет те же проходы вперёд → назад → вперёд. D и I сначала
проверяются при нулевом значении:
если уже найденный регулятор выполняет критерий, лишний поиск пропускается.
Поиск D/I ограничен 15 пробами и выполняется проходами большой шаг вперёд →
25% шага назад → 7% шага вперёд. Старый `--height-stage2` оставлен как режим
совместимости для прежнего непрерывного алгоритма высоты.

Если после падения любой этап не распознаёт возврат на землю за 15 секунд,
терминал предлагает ручное продолжение. После установки дрона на землю Enter
принимает текущую позу и повторяет ту же пробу; Ctrl+C останавливает калибровку.
Тайм-аут задаётся параметром `manual_continue_seconds`.

Контуры, которые идут позже текущего этапа, отключены. Для настройки отдельных
контуров укажите `--stage height|yaw|acceleration|velocity|position`. Остальные
коэффициенты загружаются из `--base` (по умолчанию `edu-ext`):

```sh
python -m agrotechsimapi calibrate --name my_velocity --base edu-ext --stage velocity --config calibration.json --fly
python -m agrotechsimapi calibrate --name my_position --base my_velocity --stage position --config calibration.json --fly
```

Настройки запуска из `calibration.json` переопределяют настройки базового профиля.
`host`, `sim_port`, `msp_port` управляют подключением; `hover_height` задаёт высоту
испытаний. На этапе настройки высоты она отсчитывается от положения дрона перед
каждым очередным взлётом. На этапах yaw и XY она отсчитывается от высоты, на
которой дрон находился в начале всей сессии калибровки. Для нового CLI `output_dir` всегда выбирается внутри
хранилища. Имена — до 80 букв, цифр, `_`, `-` и точек, без разделителей каталогов.

Профиль появляется только после завершения запрошенных этапов с измеренными
результатами. Закончившиеся испытания с невыполненными допусками сохраняются как
`needs_review`. Ctrl+C, потеря соединения и отсутствие пригодных проб не заменяют
старый профиль и не создают готовый новый; диагностические файлы сохраняются.
Если проба высоты не завершила посадку или дрон упал на этапе высоты/yaw,
калибратор разоружает моторы и ждёт устойчивого возврата в пределах
`ground_return_radius_m` от стартовой XY-точки (по умолчанию 1 м). Посадка
определяется по устойчивой околонулевой вертикальной скорости; возврат на
исходную отметку Z не требуется.
Для yaw направление при ручном возврате может отличаться: следующая цель всё
равно строится от курса, измеренного после служебного торможения.
Затем калибратор заново выполняет ту же пробу; её прерванный результат исключается
из подбора. Ожидание можно завершить через Ctrl+C. Если посадка после всех
проб этапа не удалась, калибратор также ждёт возврата на землю и помечает
итог этапа как `needs_review`, сохраняя уже измеренные пробы.
Старые команды `python utils/auto_calibration_tool.py ...` оставлены для
совместимости, включая `--resume-*`; они сохраняют прежний формат прогонов.
Для автоматического сохранения именованного профиля используйте новый CLI.

## Графики

```sh
python -m agrotechsimapi plot --calibration edu-ext --open
python -m agrotechsimapi plot --calibration my_position --open
python -m agrotechsimapi plot --current --last 8 --open
python -m agrotechsimapi plot --run utils/calibration_runs/20260925_115056_297226 --output report.html
```

`--current` берёт последний именованный запуск, в том числе ещё работающий;
показывает уже записанные пробы. Повторный вызов обновляет снимок один раз.
Автоматического обновления страницы нет. `--last 0` (по умолчанию) включает все
пробы. `--lang en` задаёт начальный английский язык; RU/EN можно переключать
на странице. Вкладки соответствуют пяти контурам, обе оси XY показаны вместе.
Для отдельного этапа у готового профиля отображаются также унаследованные
этапы, если их телеметрия или встроенный отчёт доступны.

## Что изменилось в клиенте

Клиент и калибратор используют `agrotechsimapi/control.py`:

* Положение → скорость → ускорение → PWM. Удалён прежний буст выхода скорости.
* Номинальные частоты из профиля: кинематика и ускорение 55 Гц, скорость 25 Гц,
  положение 15 Гц; yaw 25 Гц. Реальная частота зависит от задержек RPC.
* Скорость берётся из `linear_velocity` симулятора в мировых координатах,
  затем переводится в систему дрона. Сохранены фильтры и способ расчёта ускорения.
* Ускорение использует интеграл по времени с ограничением вклада I; остальные
  PID сохраняют расчёт по тикам, как при подборе этих коэффициентов.
* Кинематика не ждёт получения изображения: используются отдельные RPC-клиенты.
* `set_velocity_xy` теперь задаёт измеряемую скорость в м/с через каскад.
  `frame="odom"` — фиксированная мировая скорость, `base_link` — оси дрона.
* Начальные XY и yaw захватываются при подключении. Высота задаётся относительно
  начальной Z для всех целей, включая посадку. Спуск идёт ступенями 5 см с
  проверкой движения, затем посадка использует плавное снижение throttle.
* Сохранены методы движения, камеры, маркеров, датчиков, ARM, режимов, остановки
  и старые имена методов. `connect(ip, port=5762, sim_port=8080)` использует
  указанный `port` для MSP (прежняя версия игнорировала его).

`drone_name` по-прежнему задаёт номинальную высоту взлёта. Коэффициенты теперь
берутся из выбранной калибровки; для другого дрона используйте его профиль.
`hover_height` калибратора не меняет высоту обычного `takeoff()`.

Для инспекции вызовите `client.get_control_telemetry()`: там PWM, ошибки PID,
заданные и измеренные скорости/ускорения и вклад интеграла. Формат JSON
версионирован; неизвестные функции обработки PID и несовместимые параметры
отклоняются до запуска управления. Из JSON не исполняется Python-код.

Перенос проверяется автоматическими тестами на одинаковых входных отсчётах,
сохранением/импортом профилей и установкой wheel вне репозитория. Эти проверки
не заменяют проверочный полёт нового клиента в симуляторе.
